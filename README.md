# LureCast 路亚潮汐

一个**装到安卓手机上当 App 用**的路亚钓点推荐工具：拿当前位置 → 拉实时气象与水文 → 采样岸线地形 → 给出一份**能解释为什么**的钓点榜单和拟饵建议。

- 网页版（PWA）：`index.html`，手机 Chrome 打开 → 添加到主屏幕，就是一个全屏 App，离线也能打开外壳。
- 原生壳（Capacitor + 真实 Android 工程）：`native/`，用 Android Studio 打开即可出 APK。
- 全部数据源**免 API Key**：Open-Meteo（气象/海况/汇流/高程）+ OpenStreetMap（水域/岸线）。

## 推荐是怎么算出来的

**环境分**（与点位无关，全水域共享）＝ Σ 分数 × 权重：

| 因子 | 权重 | 判断依据（要点） |
|---|---|---|
| 水温/气温 | 0.18 | 落在目标鱼的活跃区间给 100；海用实测海表温，内陆用近两日气温做代理 |
| 气压 | 0.20 | 1012–1022 hPa 且 3h 缓升最好；急降最差 |
| 风 | 0.16 | 2.5–5.5 m/s 起波最出鱼；无风闷、>8 抛投困难；黑鱼/溪流偏好小风 |
| 时段 | 0.16 | 日出日落 ±1.5h 给满分；正午强光最低 |
| 云与降水 | 0.12 | 40–88% 云量最优；降水概率 >70% 扣分 |
| 水位/潮流 | 0.18 | 河：缓涨 5–30% 最好；海：潮位变化率越大越好；湖库：近 3 日降水代理 |

**钓点分**＝ 0.50 × 环境分 + 0.40 × 点位结构分 + 0.10 × 可达性（离你多近）。

点位结构分＝ 0.40 × 岸坡 + 0.30 × 岸型（岬角/湾/直岸）+ 0.20 × 迎风岸 + 0.10 × 近岸水深估值。
目标鱼（通用/鲈鱼/翘嘴/鳜鱼/黑鱼/马口溪流/海鲈）会改这四项的偏好：例如鲈鱼要陡岸＋岬角＋迎风，黑鱼要缓浅＋湾＋背风。

**岸坡怎么来的**：在岸线取样点向两侧各 120 m / 350 m 采 DEM 高程，岸侧一定比水面高 → 得出坡度 %；
近岸 20 m 水深 = 坡度 × 20 m 的线性外推。**这是推断，不是实测水深。**

### 秋季窗口期判据（视频解析，2026-10-18）

来源：抖音「极客路亚」第 20 集《10 月翘嘴窗口期，看天气预判爆口窗口期》（73 s，按画面字幕逐条整理）。
这是**翘嘴在 10 月冷空气活动期的经验口径**，不是普适规律：

| 判据 | 视频要点 | 应用现状 |
|---|---|---|
| 看降温 | 10 月冷空气开始活动，**降温是判断窗口期的关键变量**；降温前 1–2 天是黄金窗口，其中**降温前 4–6 小时**最容易集中爆口；降温后 2–3 天水温降透，大个体应激、基本停口 | **尚未并入评分**：要算它得看逐小时气温的趋势与转折点，现有 6 因子只用到当下水温与 3h 气压变化 |
| 看气压 | **1010–1020 hPa 且稳定**最好；缓慢下降口也不错；骤降或低压鱼不爱开口 | 已覆盖大半：`pressureScore` 的高压稳定档是 1012–1022 hPa（口径接近）；但**缓降现在给 58 分（「鱼口转弱」），与视频的「缓降口不错」相反**，属需要拍板的口径冲突，先不改 |
| 看温差 | 算的是**昨天的最低温 → 今天的最高温**之差（不是今天的最高−最低）。5–8 ℃ 比较理想；>10 ℃ 容易分层，鱼悬浮在中间，午后 2–5 点饵鱼上浮、翘嘴才跟着上来 | **尚未并入评分**：`daily` 里已有昨天与未来 3 天的最高/最低温，缺的只是这条判据 |
| 迎风岸 | 风浪把饵鱼推到迎风岸，翘嘴跟过来捕食 → 选迎风岸作钓 | 已覆盖：点位结构分里 0.20 权重就是迎风岸 |

另外两条不涉及时段评分的细节：日出前 20 分钟常有一波；温差小的那几天整体更稳。

**为什么没有直接改 `engine.js`**：加第 7 个因子会等比例摊薄现有 6 个权重，每片水域的分数都会被推着走；
而 4–6 小时、5–8 ℃ 这些经验值还得按你实际水域校准。这条留给你拍板后再动，不擅自改分。
## 历史影像 · 水下结构（Sentinel-2）

这是"水下结构"唯一能规模化拿到的免费路线：**同一片水面在不同水位时期拍到的影像**。

1. **找枯水期**：跨 3 年按月分散抽 6 期 Sentinel-2 L2A（云量 <20%），对每期只读你周围 1.2 km 那一小块算水体占比，
   占比最低的那期＝库水位最低＝库底露出最多。
2. **真彩 + 水深**：读枯水期的蓝/绿/红/近红外，出两张图：真彩（露出的库底、老河道、路基肉眼可见）和
   蓝绿比水深图（Stu​​mpf 法，清水前提下越浅越偏青）。
3. **结构候选点**：把蓝绿比按 16×16 网格统计，与 3×3 邻域比较，挑出"本格明显更浅"的块 —— 水下浅脊、硬底、砂石脊。
   这些点会落到地图上，**离它 250 m 内的钓点结构分 +8**，理由里会写"历史影像：水下浅脊/硬底"。
4. **两期水位差**：再读一期丰水期，"枯水露出 / 丰水淹没"的比例就是这段水位变动幅度。

工程上的关键（踩过的坑，别踩回去）：

- `GeoTIFF.fromUrl(href, { allowFullFile: false })`：不加这个，可能整幅 190 MB 波段全下，单期 30–50 秒。
- 读取必须用**像素 window**，不能用 `bbox`：bbox 路径实测单次 42 秒（会拉整幅），window 只要 0.5–1 秒。
- 按目标分辨率**挑金字塔层级**：2.4 km 窗口要 64 px 就用 40 m 那层，别拿 10 m 全分辨率去凑。
- y 轴方向：origin 是左上（北）角，行号 = (origin_y − 纬度对应 northing) / 分辨率。
- `datetime` 必须 RFC3339 全格式，给 `2024-01-01` 会 400。
- 实测：太湖中心水体占比 100%（正向对照），整条链路约 8 秒跑完，0 条 console 错误。

**局限（写在卡片上，不藏着）**：蓝绿比在浑水/深水（>10–15 m）失效；多云地区可能 3 年内没有可用的低云影像；
这仍是"水色推断"，不是声纳测深。
## 三条命的自愈设计（实测都跑过）

1. **地名搜索**：主源 OpenStreetMap Nominatim（实测 12 个国内大湖 **12/12 命中**，并带回 lake/reservoir 类型与水域范围），
   Open-Meteo 兜底。搜到大湖时不会把你丢到湖心，而是**落到离你最近的那一侧岸边**。
2. **岸线数据（钓点的来源）**：Overpass 是免费公共服务，实测同一分钟内 `overpass-api.de` 200 / `private.coffee` 500 /
   `kumi` 500 / `mail.ru` 504 轮换。所以按 de → private.coffee → kumi → mail.ru 自动切换，失败端点冷却 3 分钟，
   再用 12 小时长缓存兜底。**不需要任何 API Key。**
3. **卫星水面兜底**：如果全部端点都挂，直接用一张 Sentinel-2 水面掩膜提岸线点（NDWI + 边界像素 + 200 m 稀疏化），
   钓点照出不误。实测把 Overpass 全部拦掉后：**15 秒出 24 个钓点**，卡片上标「卫星水面」。

## 地图上直接选点

钓点地图上**点任意位置**会弹一个小卡片：显示经纬度 + 「设为当前位置」。点一下就按那个坐标重新算环境分与钓点，
不用先开「找水域」再手填坐标（这条路径还在，两个入口并存）。

## 坐标分享与外部导航（2026-10 新增）

定位卡右上角「分享」打开分享面板，四件事都能一键做完：

- **高德导航** / **百度导航**：驾车到点。没装对应的 App 会自动回落到网页版地图（高德网页链接带
  `callnative=1`，装了 App 就自动拉起）。
- **分享位置**：调用系统分享面板（微信、QQ、蓝牙、附近分享都在里面），发出去的是一段文本：
  地名 + WGS-84 坐标 + 高德坐标 + 高德地图链接 + OSM 链接。
- **复制坐标**：三行文本直接进剪贴板，方便手动粘到任何聊天窗口。

坐标口径本来就是个坑：应用内部（GPS、OpenStreetMap、Open-Meteo）一律 **WGS-84**，
而国内地图要 **GCJ-02**（火星坐标），百度还要再偏成 **BD-09**。
`assets/share.js` 在**本机**做换算（火星坐标算法 + 百度二次偏移），
所以高德/百度打开后点位是准的，不需要你手动纠偏；国内范围外（如国外湖）自动不偏移。

不改数据的来源，也不上传任何坐标：换算纯本地，分享走系统面板。

## 影像面板：一张主图，可缩放

「影像 → 分析影像」之后只有**一张主影像**，铺满卡片宽度（左右出血），上面一行是期次下拉 + `+ / −` 缩放：

- **期次**：换一期就重读那一期的影像，主图与结构候选点一起更新；不再有「对比影像」下拉。
- **缩放**：`+` 放大（窗口 3.5 → 0.3 km 共 8 档）、`−` 缩小；窗口越小越细，但 Sentinel-2 只有 10 m，缩到 0.3 km 也就 ~30 px。
- **去掉了**原来的对比窗口地图与虚线分析框：那张小地图既占地方，又和主图重复。
- 图下仍保留结构候选列表，点「上图」在主地图定位。

为什么不接 Google 卫星：Google 的瓦片接口需要付费 Key，`mt1.google.com` 那种直连方式违反 ToS 且在中国区有 GCJ-02 偏移。如果你的确有 Google Maps Platform 的 Key，可以走「设置 → 底图 → 自定义 URL」把带 key 的模板填进去（费用与合规自负）。

## 分区（2026-10 改版）

顶部分段：**结论 / 钓点 / 影像 / 我的**（原来的「数据」并进「结论」，不再单独占一页）。

**罗盘现在是动态的**
- 指针用 `requestAnimationFrame` 平滑追随目标风向（走最短弧，约 0.3 s 转到位），换小时/刷新时不跳变
- 三根风线持续外扩，速度和风向一致；`性能优先` 下自动停
- 下方「风后报」可以点 **现在 / +1h / +3h / +6h**，看风怎么转（岸钓最关键的就是"风会不会转到你这一岸"）
- 数据每 10 分钟静默刷新一次（走缓存，不打断你）

- 设置面板：内容区是 flex 列，超过 90vh 时**整块滚动**（带可见滚动条），分组默认只展开第一组
**我的（全部只存本机，不联网、无上传）**
1. **常用地点**：定位或搜到点后「保存当前位置」不再只存坐标——弹窗里填 **名称 + 描述 + 最多 6 张图片**（相册/拍照两条入口，压到 480px 只存本机），保存后列表带缩略图，点「✎」可随时改名字/描述/替换图片。点一行即切换评估位置（来源标记 `fav`）；120 m 内重复会提示，最多 30 个。导出档案时这些图片一起打包。
2. **渔获档案 · 拍照解锁**：点「拍照」直接起相机，点「从相册选」走系统相册（两个入口，不再强制相机）→ 照片自动压到 480px JPEG（实测一张 240×180 压完 3 KB）→ 手动确认鱼种（**本地不做 AI 识别，避免认错鱼**）→ 记录会带上当时的鱼种、尺寸、经纬度、天气、气压与鱼口指数。配额满时会自动丢最老的照片保住记录。
3. **我的水族馆**：每解锁一个新鱼种，canvas 里就多一条会游的鱼。**鱼是真实照片素材**（本机 ComfyUI 的 Qwen-Image 生成，纯色背景 → 按键色差抠图 → WebP），25 种鱼各一张写实侧视照（共 0.86 MB）；**场景按一条实拍水下短片重做过**（2026-10-18）：
   ① 画面分三段——顶部是**从水下看到的水面**（起伏高光 + 同心涟漪）、中段是**青碧色水体 + 从水面斜射的丁达尔光柱**、底部是**砂与卵石河床**（贴图 `bed-lake.webp`，Qwen-Image 出图 1.2 MB → WebP 74 KB）+ 稀疏细草；
   ② 河床贴图按「屏幕上卵石该多大」反推缩放，再横向镜像平铺、每块错位 1.2%，4:1 的宽卡片和竖屏全屏都不会把石头放大成巨石或糊成砂纸；
   ③ 床带顶端用该高度的水体色起手渐变，不留硬边；砂床还被水色 `multiply` 浸染一层，压住照片里偏暖的砂色。
   动态：**尾巴**切成 6 段、每段绕自身前缘按正弦相位旋转（越靠尾摆幅越大，是真的「摆」不是平移）；**鳃盖**叠一层随呼吸外张的鳃区影像 + 细弧阴影；**嘴**在吻端按呼吸节奏开合（贴图本身是闭嘴的，动的是嘴上那一小片影像）；整条鱼有上下浮沉与 ±0.03 rad 俯仰。
   **按习性水层放鱼**：`species.js` 每条鱼带 `layer`（`top` 上、`mid` 中、`bot` 底，多水层写 `top|mid` 这种），水族馆把画布切成三段区间（0.18–0.34 / 0.33–0.55 / 0.55–0.645），**多水层的鱼每条随机挑一层**，所以同一缸里鲈鱼有的贴水面有的在中层；底层鱼（鳜鱼、鲶鱼、石斑、牙鲆、梭鲈）压着河床游且浮动幅度减半，不会钻进石头里。
   景深：远批鱼（`z<0.58`）画完压一层水色薄雾 → 近处鱼 → 前景细草挡在最前，远处鱼加 `ctx.filter` 模糊。素材缺失或未解码完时**自动退回矢量画法**（体征表 `FISH_FORM`）。画质自适应：连续掉帧自动降级（少焦散、关模糊、鱼整条绘制），`性能优先` 下只画静态一帧（贴图解码完会补画这一帧）。右上角按钮可**全屏**看，底部列出这个缸里每种鱼的名字与配色。生成与抠图脚本在 `native/tools/`（`fishgen.ps1` / `fishcut.py` / `fishbatch.ps1`，`fishbatch.ps1 -Force` 全量重出、`-Only bass,pike` 重出指定几种）。
   **闭嘴出图**（2026-10-18）：prompt 里显式写「lips pressed together / jaw shut / no teeth」，negative 里再排一遍「open mouth / gaping / parted lips」，已出的 25 张逐张把头剖出来验收；原来张着嘴的（尖吻鲈、白斑狗鱼、鲤鱼、海鲈、鬼头刀、军曹鱼、黄鳍金枪鱼等）用 Qwen-Image-Edit 以「把下颌抬到嘴唇相触」为指令重绘。
4. **更多 · 环境分怎么算 / 数据来源与局限**：两张说明长卡（六因子分数与权重、六个数据源的取数状态与局限）默认**收起**，点行首的「更多」展开。它们原来挂在「结论」页底部，把结论页拉得很长，现在挪到「我的」里收着，结论页一屏就能看到结论本身。

## 推荐钓点为什么看着"都一样"（已改）

数据一直是**每个点分别算的**：坐标、距离、方位、岸坡（DEM 120 m 采样）、近岸 20 m 水深估值、
迎风/背风、结构分各不相同。旧版的问题是**呈现太像**：标题全叫「千岛湖 · 中岬角」、
理由都是同样两句、拟饵三条固定不变，所以读起来像假数据。现在：

- **标题带方位**：`千岛湖 · 西北岬角`、`Lake Mendocino · 西北湾`，同一片水域的几个点一眼能分开；
  卡头还直接写出坐标（`39.2359, -123.1606`），方便你对着地图核对。
- **理由带实测数字**：`岸坡 36%（岸上 120 m 高差），近岸 20 m 约 7.2 m 深`；
  并标出"本批最陡的岸 / 本批近岸最深 / 本批最近的一个点"。
- **拟饵按这个点挑**：陡坎→德州/倒吊贴底、近岸 6 m+→铁板抽停、3–6 m→VIB、
  ≤1.5 m→水面铅笔、迎风且风≥3 m/s→亮片顺风远投、背风→轻量米诺慢抽，再补足该鱼种的经典款。

## APK 能不能"跟着仓库自动更新"

**不能直接跟随**，原因两条，都改不了：安卓不允许 App 静默替换自己（必须经系统安装器），
而且这个仓库是私有的 —— APK 里不能内置 token 去读 raw/API。

设置 →「版本与更新」里做成了**应用内检查 + 一键下载**：填一个公开可访问的更新源即可。

| 方案 | 改动生效 | 代价 |
|---|---|---|
| **A. 应用内检查更新**（已实现） | 你重新 `assembleDebug` 打成新 APK → 上传到 **公开 Release / 网盘** → 更新 `version.json` 的 build 号 | 用户点一次「去下载 → 安装」，数据不丢；适合私有代码仓库 |
| **B. 网页热更新** | 网页放到 GitHub Pages（或任意静态托管），APK 指向远程地址 → **改完即生效，不用重装** | 需要联网；仓库/Pages 要公开；离线开局能力变弱 |
| **C. 两者结合**（推荐给长期用） | APK 内置页面 + Pages 作为"最新体验通道" | 配置最灵活，但要维护两处入口 |

`version.json` 格式：

```json
{ "build": 19, "apk": "https://…/LureCast.apk", "notes": "这次改了什么", "url": "发布页" }
```

也可以直接填 GitHub Release API：`https://api.github.com/repos/owner/repo/releases/latest`
（仓库公开时可用；App 会自动取最新 release 的 `.apk` 资产与更新说明）。
鱼种库共 **25 种**（`assets/species.js`）：国内对象鱼（大口黑鲈、翘嘴鲌、鳜鱼、黑鱼、马口、白条、鳡鱼、黄颡…）+ 海水（海鲈、黑鲷、青石斑、牙鲆、蓝点马鲛、军曹鱼…）+ 全球代表种（梭鲈、虹鳟、白斑狗鱼、黄鳍金枪鱼、鬼头刀、尖吻鲈…），每条带拉丁名、科、适温区间、3 条拟饵建议和一句作钓要点。

## AI 助手（应用内 Agent，可选）

顶栏那颗四角星按钮就是助手。它不是"聊天机器人挂着玩"——**模型只能通过工具读这份应用里的真实数据**，
读不到就说没数据，不允许凭印象编温度、分数或坐标。

共 15 个工具，模型按需自己点：

| 类型 | 工具 |
|---|---|
| 读 | `app_status`（定位/水域/目标鱼/数据新鲜度）、`weather_now`、`bite_score`（环境分 + 六因子 + 时段）、`spots`（推荐钓点含理由与拟饵）、`wind_info`（风向/迎风岸分布）、`water_info`、`terrain_info`（岸坡/岬角/近水深）、`satellite_info`、`species_info`、`catch_log`（我的渔获统计） |
| 写 | `set_location`、`set_water_type`、`set_target_fish`、`goto_tab`、`refresh_data` |

每次回答的气泡上方会列出这次"查了什么/改了什么"，例如 `查 · bite_score`、`已执行 · set_water_type`，
结论怎么来的看得见。写操作只在用户明确要求时才执行，且等于替用户点了界面上同一个按钮（可再点回去）。

 **要自己配一个模型**：设置 → 识图与助手 → 选厂商 + 填 Key 就行，**识图与助手共用同一个模型**。
 DeepSeek 的 `deepseek-flash`、OpenAI 的 `gpt-4o-mini`、Gemini 的 `gemini-2.0-flash`
 本身就同时支持识图与 **function calling / 工具调用**，不用填两个模型名
 （DeepSeek 旧的 `deepseek-chat` 已下线，请求由 Flash 承接）。
 只有当这个模型不支持工具调用时（例如某些「视觉预览版」），才需要在设置里单独填「对话模型」。
OpenAI 兼容协议与 Gemini 两套都实现了（含工具的声明与回填），不用额外中转。

不配也不影响其它任何功能：点开会直接引导你去设置。Key 只存本机，坐标与渔获不会上传，
发给模型的只有"问题 + 工具取到的那些数值"。

## 存储：IndexedDB（不再是 localStorage）

`assets/store.js` 把整库读进内存、对外仍是同步接口（`Store.getItem/setItem`），落盘走 IndexedDB（库名 `lurecast`，表 `kv`）：

- **容量**：不再受 localStorage 5 MB 限制；渔获照片（每条最多 4 张 480px）、常用地点照片、卫星快照都放得下。实测一条 3 条渔获 + 全部缓存 ≈ 0.7 MB，随便加。
- **迁移**：旧版数据在首次启动时自动搬到 IndexedDB，搬完删除旧键腾出配额；面板里会显示「已迁移 N 项」。
- **写合并**：100 ms 内多次写同一批键只落一次盘（高程点级缓存刷得很勤）；切后台/关页面会强制 flush。
- **兜底**：隐私模式等 IndexedDB 不可用的环境自动退回 localStorage，功能一致。
- **清理**：设置 → 数据与本机存储 → 「清空缓存数据」只删快照与接口缓存，**不动**渔获和常用地点。

## 有争议的口径都交给用户选

天气与地形模型里没有唯一正确答案的部分，一律做成可选项（设置 → 判定口径 / 地图与路线），默认取最保守的一档：

| 项 | 默认 | 可选 | 为什么可配 |
|---|---|---|---|
| 评分偏好 | 均衡（六项按 0.18/0.20/0.16/0.16/0.12/0.18） | 气压优先 / 水温优先 / 风优先 | 钓法不同，主导因子本来就不同；三套权重都归一到 1，改完立刻重算 |
| 水温来源 | 自动（海表温→气温代理） | 手动填你测到的水温 | 内陆湖库没有免费实测水温，代理人人都知道不准 |
| 岸线兜底 | 开（OSM 取不到时用卫星水面提岸线） | 关 | 卫星掩膜会把浅滩并进水面，有人宁可不猜 |
| 路线服务 | OSRM 社区演示服务器 | 我自己的地址 / 关掉只画直线 | 公共演示机会限流，也有人要完全离线 |

## 缓存策略（这是"秒开"的来源）

| 数据 | 缓存寿命 | 依据 |
|---|---|---|
| 天气 / 气压 / 风 / 云 | 10 分钟 | 本来就 15 分钟一更新 |
| 海况 / 潮位 | 30 分钟 | 模式输出，变化慢 |
| 河道流量（GloFAS） | 3 小时 | 日尺度数据 |
| OSM 岸线（1.6 km / 4 km） | 7 天 | 岸线几乎不变 |
| 地名（逆地理） | 30 天 | 不变 |
| DEM 高程（点级，4 位小数≈11 m） | 30 天 | 地形不变 |
| **位置快照**（算好的整份结果） | 一直在，随时覆盖 | 回到同一地点先渲染它 |

机制：`stale-while-revalidate` —— 命中但过期时**先把旧数据给你用**，同时在后台静默拉新，拉完自动再渲染一次；没过期就完全不发请求。

实测（千岛湖湖心，390×844 移动视口）：

| 场景 | 出 6 条钓点卡片 |
|---|---|
| 冷启动（清空 localStorage） | 21.1 s（其中 OSM 15.3 s + 高程 1.5 s + 含卫星兜底的计算 4.3 s） |
| **同一地点二次打开** | **172 ms** |
| 第三次打开 | 171 ms |

状态条会老实写：「首次取数 21.1 s（已存本地）· 下次同一地点约 0.2 s 打开」。「数据来源」卡里还会列出本次四段耗时（气象/水文 · 高程 · 计算 · 渲染）与每个数据源的缓存年龄。
## 诚实说明（重要）

1. **没有免费全球水下地形**：暗礁、沉木、沟坎、水下陡坎这些"真结构"只有船用声呐（Garmin Quickdraw / Lowrance / 本地钓友情报）才有。本应用给的是**岸坡与岸型**，属于"能从免费数据推出来的那部分"。
2. **水位是趋势，不是读数**：GloFAS 是汇流模拟的河道流量（m³/s），不等于水位；湖库没有免费实测水位接口，用降水+汇流代理。
3. **潮位是模式值**：不是港口潮汐表，下水前以现场和官方潮汐为准。
4. **安全**：迎风岸+大风、涨水、涨潮的礁石岸都有危险，评分只谈鱼口，不谈安全。
5. 评分是启发式规则（工程经验 + 常见路亚逻辑），不是渔获统计模型；同一个点钓三次你比它准。
